## 找到并修正的路径

| 问题 | 处理 | 验证边界 |
| --- | --- | --- |
| 聊天应用私有目录里的 PDF、音频、ZIP 被拒收或误存成预览图 | 有读取授权时保存受限大小的文件副本，保留扩展名、内容和原件 | 合成文件的原始字节、导出方式和原件保留已测；真实聊天来源待测 |
| 私有图片只提供文件地址、没有独立图片数据时拒收 | 在拖入授权有效时读取，并继续做图片大小/像素校验 | URL-only 图片回归通过 |
| 另一种 URL 表示能绕过私有来源保护 | 所有文件 URL 统一进入相同规则，私有原件不作为可移动引用交出 | 回归确认原先可提供 move，修正后不提供 |
| 不可用的视频被缩略图顶替，或空视频显示成已收集 | 缺失的视频报错，空视频不加入；不把预览图当视频 | 缺失、缩略图和零字节场景已复现并通过修正回归 |

## 首批测试一次性实测清单

1. 同一段微信视频拖入 Clipio，再拖到 Finder 打开，确认是完整视频；再试一个聊天里的 PDF 或音频，原件保留。
2. 在设置里清除并重新录一个快捷键，关闭设置后用新快捷键打开；测试 Tab 切换和 Esc 退出。录入卡住的原反馈仍需确认，不能只凭监听修复宣称已解决。
3. 用临时测试文件核对普通拖到 Finder 的移动、Pin 后的复制，以及拖到聊天附件框后卡片清理；确认磁盘原件变化符合各自预期。
4. 另一台 Mac 安装候选包后，从“应用程序”打开，确认菜单栏和快捷键入口可用。先前反馈者“系统设置列表没有 Clipio”的问题仍未复现，需要该机器的 macOS/Clipio 版本及运行状态。

## 对外测试说明需要写清

- 私有应用来源的保存副本仍有单项 64 MiB、默认总计 128 MiB 限制。较大文件先保存到 Finder，再拖入以保留位置；普通文件引用不复制整份内容。
- 只在放手后生成文件、且不能预先确认大小的来源仍需先另存到 Finder；本轮没有无界接收这些临时文件。
- 自动移出依据目标接受拖入，不代表聊天消息发送或后续上传成功。
- macOS 14 起、Apple silicon / Intel 通用构建是分发目标；另一台 Mac、Intel 实机、不同系统版本及跨卷移动仍需测试者实测。

反馈至少包含：Clipio 版本、macOS 版本、文件来自哪个应用、文件类型、拖到哪里、是否 Pin，以及实际提示。无需上传剪贴板数据库或整个设置目录。
