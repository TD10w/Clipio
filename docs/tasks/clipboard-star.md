# 后续规划：剪贴板 Star 收藏

状态：已按授权做出独立可回退候选；测试与编译通过，最终交互及旧数据升级待体验；未安装、未发布。

来源：用户于 2026-11-11 口述，要求“之后聊一下怎么设计，先存一下”，随后指定存到 Clipio 的后续规划里。

## 需求

给剪贴板内容标记 Star 后保存起来，方便以后找到并直接粘贴、反复使用。

典型用途：个人网站、LinkedIn、社交媒体及其他常用链接。

## 已确认（2026-11-11，grill-with-docs 第一轮）

- 收藏长期保留，直到用户主动取消收藏或删除；普通清空历史不影响收藏。
- 保留剪贴板已有的内容能力，图片明确可收藏，不限定为链接与文字。
- 沿用现有 Clipio 的复制、粘贴操作，不新增一套取用方式。

来源：用户原话“一，是，二，图片应该可以保留吧，就是clipboard的功能。三，是的。”

## 已确认（2026-11-11，第二轮）

- 剪贴板 Pin 直接改成 Star，原来 Pin 住的内容自动成为收藏；收集区 Pin 保持原来的作用。
- 剪贴板内部增加“全部 / 收藏”切换，不新增第三个主入口。
- 每项收藏可自行取名，非必填；名称不改变复制或粘贴的原内容。

来源：用户对 Q4–Q6 回复“1. 可以 2. 可以，怎么搞，shift+tab 切换吗？3. 是”。Shift+Tab 是用户提出的快捷键候选，需核对现有键盘行为再决定。

## 待后续讨论

- “全部 / 收藏”的快捷键与焦点规则；重新打开时默认的筛选范围。
- 收藏名称的编辑入口，以及是否允许修改原内容。
- 取消收藏、主动删除、清空全部等边界；文件引用是否另有保留要求。

按 grill-with-docs 继续讨论并记录决定，用户确认已达成共同理解前不开始实现。

## 清空入口与打开规则预览（2026-11-11）

- 用户明确不希望再加一个图标。现有顶部垃圾桶、设置、电源按钮保持数量不变。
- 当前提案：点击原垃圾桶，菜单里明确区分“清空历史（保留收藏）”和“清空全部（含收藏）”；后者另做明确确认。不再依赖 Shift 换成斜线垃圾桶传达范围。菜单形态尚待看预览确认，不把用户的疑问算作已批准新增图标。
- 用户对按最近动作自动选择范围仍不确定，并请代理给经验判断。代理建议收窄：外部新复制后，下次打开回全部并清旧搜索；其他时候记住手动范围。点 Star 不自动改页面或下次范围；已经打开时不突然跳页。用户后续手动选择优先于更早的复制事件。该简化方案尚待确认，不覆盖先前候选的原始记录。

## 只读能力核对（2026-11-11）

以下为源码事实，不代表新增设计已确认或已在日用版验收：

- 现有剪贴板 Pin 已能免于条数淘汰与普通清空；主动删除、清空全部仍会移除 Pin。当前按住 Shift 的清空入口会走清空全部，Star 的相应保护与提示待讨论。
- 普通复制图片的数据随历史保存；文件 URL 通常仍是原文件引用，不等于保存了文件副本。通用剪贴板图片的文件回退也可能依赖外部文件；长期保留这些内容的语义待讨论。
- Pin 与字母快捷键共用字段，但可用字母耗尽不构成硬收藏数量上限：空字符串也仍被识别为 Pin，只是没有有效的独立字母快捷键。不能把快捷键数量直接当作可保留数量。
- 已有改名和文字内容编辑能力；编辑富文本会转换成纯文本。图片/文件不走文字值编辑；如复用编辑入口，需要核对预览刷新。
- 重复复制会保留原 Pin 和名称；现有复制、粘贴、无格式粘贴可复用，自动粘贴仍沿用既有辅助功能授权。

核对来源：`Clipio/Observables/History.swift`、`Clipio/Models/HistoryItem.swift`、`Clipio/Clipboard.swift`、`Clipio/Settings/PinsSettingsPane.swift`、`Clipio/Views/HeaderView.swift`。Q4–Q6 已于第二轮确认；快捷键仍待核对与决定。
