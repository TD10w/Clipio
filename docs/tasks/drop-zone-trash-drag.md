## 2026-11-11 修复进展

- 代码缺口：拖出仅声明 move/copy，没有 Dock Trash 使用的 delete；结束回调也忽略 delete。依据 [Apple 拖动源说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/DragandDrop/Concepts/dragsource.html)。
- 无 Pin 的批次增加 delete 操作；含 Pin 的批次继续保持原有移动/复制保护，不开放 delete。Pin 删除语义仍待产品讨论。
- delete 回调沿用现有移动核对：只有导出文件确实离开原位置才移除对应非 Pin 卡片。部分完成只移除已完成项；延迟完成使用文件事件监听；取消或未移动保留卡片。
- 文件操作仍由系统目标处理；Clipio 不主动 trash/delete 本地原件，不更改只读书签或沙箱权限。**Dock 是否实际移动文件、真实拖放是否成功，尚无本次实机证据，不能以单元测试替代。**

## R2：用户普通文件体验未通过后的修正

用户明确报告普通文件或文件夹拖向 Dock 废纸篓仍无反应。R1 只能等文件自行离开路径，没有实现 Dock delete 请求对应的实际系统回收，且旧只读授权无法执行回收。R1 不计为实机修复完成。

R2 使用 NSWorkspace.recycle 执行回收，仅清理系统逐项确认的非 Pin 卡片；失败及部分失败保留相应项并显示原因。原件身份、Pin 子项和异步操作锁增加保护，不做永久删除回退。选入文件权限改为 user-selected.read-write，范围仅限用户主动选入的文件/文件夹；旧只读条目需从 Finder 重新拖入一次更新授权，保留原卡片、Stack 与 Pin。

外部沙箱对照实测：冷启动只读书签回收失败（513）；仅用户选入的可操作授权回收成功。实际产品代码的旧书签更新、ID/Pin 保留及冷启动后文件/文件夹回收均用外部合成内容验证成功，已恢复测试原件。真实 Dock 鼠标落放仍待 R2 体验。
