# Liquid Glass 与文件收集人工验收

当前范围为设计分支的原生材质、系统字体及文件收集。小马图标继续使用原版，简化概念已否决。自动化结果与限制见 [项目交接](beta-readiness-handoff.md)。

## 打开与准备

1. 先从菜单栏退出正在使用的旧 Clipio，避免两个应用抢占 ⌘⇧V／⌘⇧C。
2. 在 Finder 按 ⌘⇧G，进入项目下的 `build/人工验收/`，双击 `Clipio测试版.app`。这是本地调试构建，不是公开安装包。首次需要剪贴板或辅助功能权限时，按系统提示选择；尚未授权时，自动粘贴可能无法验收。
3. 测试版标识为 `com.clipio.app.manualacceptance`，保留沙箱并使用独立偏好与数据容器。正常运行，不使用自动化的临时内存模式，因此可以验收重启保留。构建前已核对原版 AppIcon 资源与主线一致。
4. 同目录 `测试素材` 提供文字文件、文件夹及原版图标 PNG。把待拖出文件放到新的目标文件夹中。第一次用这些示例测试即可。

## 一次走完的清单

| 操作 | 预期与关注点 |
| --- | --- |
| 复制中文、长英文、网址、图片和颜色值，再按 ⌘⇧V | 形成不同卡片；文字可读，边框清楚，图片正常。点击／回车能取用，鼠标悬停预览对应正确卡片。 |
| 在搜索框输入中文并选词，再搜索已有内容 | 输入法正常完成组合输入，结果正确；清空后恢复全部卡片。 |
| 按 ⌘⇧C，再点标题旁图标或按 Tab | 剪贴板／文件收集正常切换。分别输入不同搜索词，来回切换后各自保留。 |
| 把多个示例文件和文件夹拖入收集面板 | 每项各出现一张卡片。未展开时也检查顶部收集入口能否接收拖入，并正确显示数量。 |
| 把普通项拖到 Finder 目标文件夹 | 目标收到文件后，普通项从收集区消失；原文件仍在。取消拖动或拖到无效位置，项目应保留。 |
| 右键某项选择 Pin，再拖出 | 目标收到文件，收集区内 Pin 项保留。混选普通项和 Pin 项拖出，普通项移除、Pin 项保留。 |
| 从 Safari／Chrome 的网页直接拖一张图片进来，再拖到 Finder | 收集区保存成可用图片；拖到 Finder 后可打开。记录浏览器和页面；部分网站提供链接或不允许拖图，需要单独判断。 |
| 留下一个普通项和一个 Pin 项，从面板电源按钮退出，再双击测试版打开 | 两项均保留且仍能拖出。之后重启 Mac 再重复，检查外部文件授权。 |
| 点击收集区清空并确认 | 普通项清空，Pin 项保留，原件不被删除，剪贴板历史不受影响。 |
| 切换 macOS 浅色／深色、降低透明度；在内建／外接屏分别唤出 | 文字与选中态可辨认，材质不过亮；入口与面板不被刘海遮住，鼠标和键盘操作正常。 |

Pin 可使用右键菜单，默认快捷键为 ⌥P；删除默认 ⌥⌫。先用右键可避免记快捷键。

## 反馈与结束

反馈用“第几项 + 实际现象 + 希望怎样”即可，例如“第 5 项，拖出取消后卡片消失了”。截图可附上，但不必整理技术日志。

测试后退出测试版，再打开原来的 Clipio。测试版数据保留在独立容器中，后续可继续复测。真实目标收到拖放只说明系统接受文件，不代表聊天消息已经发送或上传已完成。
